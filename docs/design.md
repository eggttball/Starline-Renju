# 連珠遊戲設計（2026-10-28）

在 `renju/` 建立獨立、繁體中文、可於桌面與手機操作的網頁版連珠。使用零額外依賴的 Node.js HTTP 伺服器，以及原生 HTML、CSS、ES modules。既有課堂網站不需要更動。

## 規則與開局

採國際連珠聯盟官方 https://www.renju.net/rifrules/ 的傳統 RIF 開局流程（與 Taraguchi-10 區別）：暫定黑方提出標準三子開局，暫定白方選擇交換或保持；確定白方下第四手；黑方提出兩個不等價的第五手；白方選擇保留其一，再下第六手。第五手等價性由保持既有四子盤面不變的八種棋盤對稱變換判定。

15×15 棋盤。黑方長連、四四、三三為禁手，精確五連依官方 §9.2 優先勝利；白方五連或長連勝利。活三必須能藉合法延伸形成直四，排除假三並遞迴判定延伸點的三三。實際下出黑棋禁手判白方勝；無效 API 回應仍暫停重試，不將服務錯誤算成比賽禁手。正常結束為黑五、白五／長連、黑禁手敗或雙方同意和棋。放棄比賽則移除該局，不列入歷史。

## 模式與電腦

持黑、持白、雙人模式。單人選項代表暫定顏色；開局交換後，玩家與電腦角色隨之交換。所有角色、階段與行動按目前盤面狀態決定。雙人模式由同一裝置操控双方。

提供 26 標準開局的選單、預覽及三子提案。電腦提案使用 `min(p, 1-p)` 評估對手自由交換後的最差勝算。開局資料保留來源、資料性質及樣本數；如無可靠實測資料，清楚標示理論評估／未知，不宣稱虛構統計勝率。允許使用者在資料檔填入自己的勝率與來源。

白方與開局階段用本地戰術評分（勝棋、阻擋勝棋、威脅、中心距離）。正式對局每次電腦黑棋行動必須請求伺服器 `/api/agent`。缺少設定、逾時、無效或禁手回應時保留盤面、顯示原因並允許重試；不自動以本地棋力替代黑棋 API。

## API 與金鑰

伺服器讀取 `renju/.env`，提供 `AI_API_KEY`、`AI_API_ENDPOINT`、`AI_API_MODEL`、`AI_API_FORMAT`。支援 `agent-json`、`openai-chat`、`openai-responses` 格式。使用者稍後提供實際 endpoint 時可調整 adapter，不需重寫遊戲。瀏覽器僅接收是否已設定；金鑰與 .env 不透過靜態檔案服務。伺服器驗證盤面與輸入，重新計算合法黑棋點，再驗證 agent 回應。API 回傳 `{move:{row,col},reason}`，零起算座標。

## 使用介面與驗證

暖白／木色棋盤、深色棋子、金色重點；清楚顯示目前行動方、開局步驟、交換角色、API 連線狀態與棋譜。鍵盤方向鍵、Enter 落子；提供落點預览、禁手提示、棋譜匯出與手機版佈局。主畫面列出全部歷史賽局，提供查看棋盤及完整棋譜。

## 持久保存（2026-10-28 補充需求）

使用版本化 localStorage 封裝，保存完整未完成賽局（含 ID、建立時間、交換角色及未完成的第五手提案）及正常完成歷史。每次成功變更先保存再顯示；关闭頁面、重啟電腦後載入未完成局。新局不得直接覆蓋未完成局；必須先正常結束或明確「放棄比賽」。存取失敗明確顯示原因，保留上一個已保存狀態。正常完成只記一次，同 ID 更新不重複。

## 電腦勝率棋譜（2026-10-28 補充需求）

私有伺服器資料檔 `.renju-data/ai-book.json` 保存局面、顏色、落點與最新評估勝率，棋盤八種對稱視為同局並映回落點。新走法若勝率 ≥0.70 或 <0.40 則記錄；已記錄走法無論新勝率多少均更新成最新值，不保存歷史最高值。≥0.70 的合法記憶走法下次自動沿用；0.40–0.69 不直接沿用，重新評估；<0.40 優先排除，只有沒有其他合法走法時再容許。

電腦黑棋即使沿用高勝率記憶，仍按原要求每手詢問 API 重新評估該點；新評估變低會影響下次沿用。API 回應新增 `winRate`（0–1，估計值，不宣稱統計校準）；舊服務缺少此值可下棋但不學習。電腦白棋普通手透過本機 `/api/white` 使用相同記憶策略，API 已設定時也請求遠端評估；未設定時採本地戰術，僅將可直接證明的立即勝棋記為 1，一般戰術評分不冒充勝率。

使用 Node 原生測試驗證黑白勝負、禁手、假三、同方向四四、開局交換、第五手等價、交換感知評估及 API 錯誤／密鑰隔離；用瀏覽器檢查桌面與手機版流程。實際遠端 API 呼叫待使用者提供 endpoint/key 後才能驗證。
