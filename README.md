# 連珠 RENJU

獨立的繁體中文網頁遊戲，採 **傳統國際 RIF 規則**：15 路棋盤、26 種三子開局、交換、兩個不等價的第五手，以及黑棋禁手。支援你持黑、你持白、同機雙人。

## 啟動

需要 Node.js 22 以上。遊戲執行不需安裝套件。

```sh
cd /Users/egghsu/renju
npm start
```

開啟 <http://127.0.0.1:3000>。這是独立伺服器，現有 classroom 網站不需要更動。預設提供本機使用；若要公開部署，需先調整伺服器的 host/origin 與存取控制，且 API 需要一併部署。直接開 HTML 或只用靜態 Firebase Hosting 無法使用此 Node API。

未設定 API 仍可玩雙人模式或以人類持黑對電腦白棋；若開局交換使電腦改持黑，完成開局後的一般局面會等待 API 設定。開局階段與未設定 API 的白棋採本地戰術評分，並不宣稱專業棋力。設定 API 後，電腦白棋也會請求 AI 評估，以更新勝率棋譜。**電腦先檢查立即連五、必擋四與可證明的禁手攻擊，直接落子；其餘正式對局中的黑棋走法詢問遠端 API，失敗時暫停。**

## Key 放哪裡

把 `renju/.env.example` 複製為 **`renju/.env`**：

```sh
cp .env.example .env
```

用編輯器填入：

```dotenv
AI_API_KEY=你的金鑰
AI_API_ENDPOINT=完整的API網址
AI_API_MODEL=服務要求的模型名稱
AI_API_FORMAT=openai-chat
HOST=127.0.0.1
PORT=3000
```

修改後重新啟動 `npm start`。網頁會顯示「黑棋 AI 已設定」；暫停的對局可按「重新詢問 AI」。Endpoint 必須包含完整路徑，伺服器不自動補 `/v1` 等路徑。

`.env` 已由本資料夾的 `.gitignore` 排除。Key 僅由伺服器讀取，瀏覽器及靜態檔案服務都不會取得。也可透過作業系統環境變數設定同名欄位；環境變數優先於 `.env`。請勿把真實 key 放入 HTML、`app.mjs` 或勝率資料。

## API 格式

三種格式皆使用 `Authorization: Bearer <AI_API_KEY>`。服務若使用其他授權標頭、工具呼叫或特殊封裝，收到實際 endpoint 文件後只需調整 `lib/agent.mjs`。

| `AI_API_FORMAT` | 傳送格式 | 解析回應 |
| --- | --- | --- |
| `openai-chat` | `{model,messages:[system,user]}` | `choices[0].message.content` 中的 JSON |
| `openai-responses` | `{model,instructions,input}` | `output_text` 或 `output[].content[]` 的 JSON |
| `agent-json` | 下方直接 JSON，model 可留空 | 直接回傳 `{move,reason}` |

自訂 agent 收到以下盤面資料（此範例節省篇幅，`board` 實際固定 225 格、`moves` 為完整棋譜）：

```json
{
  "rules": "RIF",
  "board": [0, 0, 0],
  "moves": [{"row": 7, "col": 7, "color": 1}],
  "color": "black",
  "legalMoves": [{"row": 8, "col": 9}],
  "request": "Choose exactly one legal black move. Return only JSON..."
}
```

回傳：

```json
{"move":{"row":8,"col":9},"reason":"阻擋對手威脅並保留進攻機會。","winRate":0.72}
```

`row`、`col` 必須是 **0–14 整數**；左上角 A15 是 `(0,0)`，中心 H8 是 `(7,7)`；`color` 為 `0` 空、`1` 黑、`2` 白，API payload 的 `color` 則是 `black` 或 `white`。`reason` 為最多 1000 字元的字串。`winRate` 使用 **0–1 的數字**，代表「當前電腦持棋方」下這一步後的最新估計勝率；這不是已校準的實測統計。舊 API 缺少 `winRate` 仍能下棋，但這次不更新記憶；如要啟用學習，請讓 API 回傳此欄位。

伺服器只在開局完成且輪到對應顏色時接受請求，重新計算全部合法點，並再次驗證 agent 落點。HTTP 錯誤、45 秒逾時、無效 JSON、占用或禁手落點都會暫停並保留盤面，可修復後重試。放棄對局會取消瀏覽器請求，並向遠端 API 傳遞取消訊號。

目前已使用模擬遠端服務測試三種格式；實際 API 相容性需在提供 endpoint、模型與授權方式後驗證。

## 開局與勝率

RIF 流程：暫定黑方提出三子 → 暫定白方交換／保持 → 確定白方下第四手 → 黑方提出兩個不等價第五手 → 白方保留其一並下第六手 → 正式對局。

持黑／持白選項代表**暫定顏色**，交換後人類與電腦會跟著換色。第五手是否等價，使用保持當前四子彩色盤面不變的八種棋盤對稱變換判定。

電腦提出開局以 `min(p, 1-p)` 考慮對手自由交換後的最差勝算。例如若某開局的可靠黑勝率是 100%，交換後提案方最差勝算為 0%，便不會比均衡開局優先。

目前官方來源沒有可校準的完整 26 局實測勝率表，因此**沒有填入虛構百分比**。預設以世界冠軍 Ando Meritee 的 1997 年歷史評述，優先選擇疏星、松月、丘月、斜月；這不是目前完美棋力的結果或統計勝率。花月／浦月僅列為暫定黑方優勢評估，無實測率或經核驗的必勝證明。未知局型也不視為已證明均衡。

可在 `data/opening-rates.json` 填入自己的資料：

```json
{
  "id": "d3",
  "blackWinRate": 0.52,
  "rateKind": "empirical",
  "sampleSize": 1000,
  "assessment": "balanced",
  "source": "https://example.com/你的資料來源"
}
```

這是資料格式示例，**不是疏星的真實勝率**。`blackWinRate` 使用 0–1，未知為 `null`；`rateKind` 可為 `empirical`（實測）、`theoretical`（有可靠證明的理論結果），或 `unknown`。保留來源與樣本數，確認資料使用同一 RIF 開局規則；和棋需以一致方法計入估值，才能比較。刷新網頁後載入新資料。

參考資料與規則原文詳見 [docs/sources.md](docs/sources.md)。

## 禁手與操作

黑棋精確五連勝；白棋五連或長連勝。黑棋長連、四四、真正的三三為禁手，包含同方向兩個四；活三需能合法延伸為兩端開放直四，延伸點的禁手會遞迴判定，排除假三。依官方 §9.2，同手形成精確五連時優先獲勝。

實際落下黑棋禁手會立即判白方勝，並保留禁手落點於歷史棋譜。無效 API 回應會暫停重試，不把服務錯誤當成比賽禁手。電腦預設接受人類的和棋提案，同機雙人需另一位玩家按同意。棋盤固定 **15×15、225 個交叉點**，支援方向鍵移動與 Enter 落子、最後一手標記、手數切換及 JSON 棋譜匯出。

電腦優先立即連五；否則先擋對方衝四或跳四的成五點。白棋若能衝四，且唯一防守點是黑棋禁手、黑棋也沒有下一手連五，就直接採用此攻擊。這些走法先於勝率記憶，不呼叫遠端 AI，也不等待思考延遲。禁手攻擊後仍按實際落子判決：黑棋落禁手才判禁手敗，黑棋下在其他點則由白棋下一手連五。

思考期間，棋盤上的 `?` 標記是本地建議的候選點；AI 最終落點可能不同。最後一顆電腦棋子旁顯示電腦持棋方的評估勝率。立即勝棋或可證明的禁手攻擊標為 `100%`；未經 AI 評估的防守及一般本地走法標為「未評估」。勝率會與棋譜一同保存，續局、歷史查看及 JSON 匯出均保留。

## 自動續局與歷史賽局

每局建立固定 ID，成功變更會先保存到浏览器 `localStorage` 的 `renju.archive.v1`。開局、交換後角色、未選完的第五手、完整盤面與棋譜都會保存。關閉頁面或重開電腦後，使用**同一瀏覽器、同一網址來源（含埠號）**開啟會自動續局。清除瀏覽器網站資料或使用不保存資料的模式會移除這份資料。

未完成對局不能被「新對局」或模式切換覆蓋。正常結束後（黑五、白五／長連、黑禁手敗、雙方和棋），本局列入主畫面歷史紀錄；可查看完整棋盤與棋譜，也可匯出。選擇 **「放棄比賽」** 會移除當前未完成局，且不加入歷史。瀏覽器儲存失敗時保留上一個已保存局面，顯示原因。

## 電腦的勝率棋譜

私有資料在 `renju/.renju-data/ai-book.json`，第一次符合記錄條件時自動建立。此檔案已排除 git，且不透過 HTTP 提供。它依完整 15×15 局面、電腦顏色及落點記錄；八種旋轉／鏡射局面視為相同，並將記憶落點映回當前棋盤。

| 最新評估 | 記錄與下一次行為 |
| --- | --- |
| ≥70% | 記錄；下次直接沿用合法記憶走法，最高勝率優先 |
| 40–69% | 新走法不加入；已記錄走法更新成此最新值，下次重新評估 |
| <40% | 記錄；下次先排除此點，有其他合法選擇時不選它 |

例如 `72% → 80% → 65% → 35%`，記憶會依序覆寫成最新數字；不保留最高值冒充目前勝率。沒有更好的候選（所有合法點都已被標為低勝率）時，才允許重新考慮低勝率點。

一般局面中，電腦黑棋沿用 ≥70% 的記憶時仍呼叫 API，讓 agent 重新評估指定的 `preferredMove`。服務須回傳該點；新評估變低會影響下次沿用。API 已設定時，白棋也用相同評估／記憶策略。強制戰術優先於記憶；可直接證明的立即勝棋與禁手攻擊記為 `1`，未評估的防守不改寫已有勝率。一般戰術分數不冒充勝率。這套記憶記錄 agent 的評估，與開局資料的實測勝率分開。

## 檔案與驗證

| 檔案 | 用途 |
| --- | --- |
| `index.html`、`styles.css`、`app.mjs` | 畫面與玩家操作 |
| `lib/rules.mjs` | 黑白勝負與遞迴禁手 |
| `lib/game.mjs` | RIF 階段及顏色交換 |

| `lib/book.mjs` | 私有胜率棋譜與對稱映射 |

規則、流程、UI 與伺服器測試：

```sh
npm install
npm test
```

`jsdom` 只用於測試，沒有執行時套件依賴。伺服器測試需可使用本機 loopback 埠。
